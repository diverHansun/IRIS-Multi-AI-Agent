# 虚拟文件系统实现细节

## 1. 概述

虚拟文件系统是一个完全内存化的文件存储系统，基于 LangGraph 的状态管理和持久化存储实现。所有文件数据存储在 Agent 的运行时状态中，与宿主机文件系统完全隔离。

---

## 2. 核心数据结构

### 2.1 FilesystemState

虚拟文件系统的状态存储在 LangGraph 的 AgentState 中：

```python
class FilesystemState(AgentState):
    files: Annotated[Dict[str, FileData], _file_data_reducer]
```

**关键特性：**

- `files` 字段是一个字典，键为虚拟路径，值为文件数据
- 使用自定义 reducer 函数支持文件的增量更新和删除
- 状态在整个会话期间持久化

---

### 2.2 FileData

单个文件的数据结构：

```python
class FileData(TypedDict):
    content: List[str]      # 文件内容按行存储
    created_at: str         # ISO 8601 格式的创建时间
    modified_at: str        # ISO 8601 格式的修改时间
```

**设计考虑：**

- 按行存储便于行号显示和分页读取
- 时间戳记录文件的生命周期
- TypedDict 提供类型安全

---

### 2.3 文件数据 Reducer

```python
def _file_data_reducer(
    current: Dict[str, FileData] | None,
    updates: Dict[str, FileData | None]
) -> Dict[str, FileData]:
    # 支持增量更新
    # None 值表示删除操作
```

**功能：**

- 合并多个工具调用的文件更新
- 支持文件删除（通过传递 None 值）
- 处理状态初始化

## 3. 长期记忆机制

### 3.1 设计理念

虚拟文件系统支持两种存储模式：

**短期存储：** 文件存储在 AgentState 中，会话结束后清除
**长期存储：** 文件存储在 LangGraph Store 中，跨会话持久化

---

### 3.2 路径前缀区分

通过路径前缀区分存储位置：

- 普通路径（如 `/workspace/temp.txt`）：短期存储
- 记忆路径（如 `/memories/notes.txt`）：长期存储

---

### 3.3 存储命名空间

长期存储使用 LangGraph Store 的命名空间机制实现隔离：

```python
namespace = (assistant_id, "filesystem")
```

**隔离级别：**

- 不同 Assistant 的文件相互隔离
- 同一 Assistant 的文件跨会话共享
- 支持分层命名空间

---

### 3.4 Store 操作

**写入长期存储：**

```python
store.put(namespace, file_path, file_data)
```

**读取长期存储：**

```python
item = store.get(namespace, file_path)
file_data = convert_store_item_to_file_data(item)
```

**列举长期存储：**

```python
items = store.search(namespace)
file_paths = [item.key for item in items]
```

## 4. 大结果驱逐机制

### 4.1 驱逐触发条件

当其他工具的输出超过配置的 token 限制时，自动将结果存入虚拟文件系统。

**默认阈值：** 20,000 tokens（约 80,000 字符）

---

### 4.2 驱逐流程

1. 检测工具输出大小是否超过阈值
2. 生成驱逐文件路径：`/large_tool_results/{tool_call_id}.txt`
3. 将完整输出保存到虚拟文件
4. 返回简化消息，包含文件路径和前 10 行预览
5. Agent 可以后续使用 `read_virtual_file` 分批读取

---

### 4.3 驱逐文件组织

**目录结构：**

```
/large_tool_results/
  ├── {tool_call_id_1}.txt
  ├── {tool_call_id_2}.txt
  └── ...
```

**特点：**

- 自动生成唯一文件名
- 不会与用户创建的文件冲突
- 会话结束后自动清理

## 5. 工具实现

### 5.1 list_virtual_files

**功能：** 列出虚拟文件系统中的所有文件

**参数：**
- `path`（可选）：目录前缀过滤

**返回：** 文件路径列表

**行为：**
- 从 AgentState 获取所有文件路径
- 如果启用长期记忆，合并 Store 中的文件
- 支持按路径前缀过滤

---

### 5.2 read_virtual_file

**功能：** 读取虚拟文件内容

**参数：**
- `file_path`：文件路径（必须是绝对路径）
- `offset`：起始行号（默认 0）
- `limit`：读取行数（默认 2000）

**返回：** 带行号的文件内容

**行为：**
- 路径验证和规范化
- 根据路径前缀判断从 State 还是 Store 读取
- 支持分页读取大文件
- 空文件返回系统提醒

**输出格式：**

```
     1  line content 1
     2  line content 2
     3  line content 3
```

---

### 5.3 write_virtual_file

**功能：** 创建新的虚拟文件

**参数：**
- `file_path`：文件路径
- `content`：文件内容

**返回：** 成功消息或错误提示

**行为：**
- 检查文件是否已存在（存在则拒绝）
- 路径规范化
- 根据路径前缀决定存储位置
- 自动生成创建和修改时间戳
- 更新 AgentState 或 Store

---

### 5.4 edit_virtual_file

**功能：** 编辑已有虚拟文件

**参数：**
- `file_path`：文件路径
- `old_string`：要替换的字符串
- `new_string`：替换为的字符串
- `replace_all`：是否替换所有匹配（默认 False）

**返回：** 成功消息或错误提示

**行为：**
- 精确字符串匹配替换
- 默认只替换第一个匹配
- 匹配数为 0 或大于 1 时报错（除非设置 replace_all）
- 保留创建时间，更新修改时间
- 更新 AgentState 或 Store

---

## 7. 配置选项

### 7.1 配置文件位置

```
config/agents/deep/middleware/filesystem/virtual_filesystem.json
```

---

### 7.2 配置文件结构

```json
{
  "enabled": true,
  "long_term_memory": true,
  "tool_token_limit_before_evict": 20000
}
```

---

### 7.3 配置参数详解

#### 7.3.1 enabled

**类型：** 布尔值

**默认值：** `true`

**说明：** 控制是否启用虚拟文件系统中间件

**作用：**
- `true`：加载虚拟文件系统，向 Agent 提供文件操作工具
- `false`：禁用虚拟文件系统，Agent 无法使用虚拟文件工具

**使用建议：**
- 绝大多数场景建议启用
- 仅在确定不需要文件存储功能时禁用

---

#### 7.3.2 long_term_memory

**类型：** 布尔值

**默认值：** `false`

**说明：** 控制是否启用长期记忆功能，将文件持久化到 LangGraph Store

**前置条件：**
- 需要正确配置 LangGraph Store
- Runtime 必须提供 `store` 实例

**作用：**
- `true`：Agent 可以使用 `/memories/` 路径前缀创建跨会话持久化的文件
- `false`：所有文件仅在当前会话有效，会话结束后清除

**存储隔离：**
- 按 `assistant_id` 隔离，不同 Assistant 的长期文件互不干扰
- 命名空间：`(assistant_id, "filesystem")`

**使用建议：**
- 需要跨会话保留知识库、配置文件时启用
- 纯临时计算场景可禁用，减少存储开销

**示例场景：**

| 场景 | 是否启用 |
|------|----------|
| Agent 需要记住用户偏好设置 | 启用 |
| Agent 构建长期知识库 | 启用 |
| Agent 仅做一次性数据处理 | 禁用 |
| 测试环境，避免污染存储 | 禁用 |

---

#### 7.3.3 tool_token_limit_before_evict

**类型：** 整数或 `null`

**默认值：** `20000`

**说明：** 其他工具输出超过此 token 数时，自动将结果驱逐到虚拟文件系统

**计算规则：**
- 1 token ≈ 4 字符（英文）
- 20000 tokens ≈ 80000 字符 ≈ 80 KB 文本

**驱逐行为：**
1. 监控所有非文件系统工具的输出
2. 当输出长度超过 `token_limit * 4` 字符时触发驱逐
3. 完整输出保存到 `/large_tool_results/{tool_call_id}`
4. 工具消息替换为简化提示，包含文件路径和前 10 行预览
5. Agent 可后续使用 `read_virtual_file` 分页读取完整内容

**禁用驱逐：**
- 设置为 `null` 或省略此参数
- 所有工具输出直接返回给 Agent（可能导致 context 溢出）

**调优建议：**

| Token 限制 | 适用场景 |
|-----------|----------|
| 10000 | 小型模型（context 限制 < 32K） |
| 20000 | 中型模型（context 32K-128K）  |
| 50000 | 大型模型（context > 200K）    |
| null | 模型 context 极大，或确定工具输出很小 |

**注意事项：**
- 驱逐会增加一次额外的文件读取工具调用
- 如果工具输出结构化（JSON、表格），驱逐后 Agent 需要重新解析
- 驱逐文件在会话结束后自动清理，不占用长期存储

---

### 7.4 配置示例

#### 极简配置（推荐）

```json
{
  "enabled": true,
  "long_term_memory": false,
  "tool_token_limit_before_evict": 20000
}
```

**适用场景：** 单次对话任务，不需要跨会话记忆

---

#### 启用长期记忆

```json
{
  "enabled": true,
  "long_term_memory": true,
  "tool_token_limit_before_evict": 20000
}
```

**适用场景：** 多轮对话，需要保留知识库、用户偏好等

**前置要求：** 配置 LangGraph Store

---

#### 禁用驱逐（大 context 模型）

```json
{
  "enabled": true,
  "long_term_memory": false,
  "tool_token_limit_before_evict": null
}
```

**适用场景：** 使用 Claude Opus 等超大 context 模型

---

#### 完全禁用虚拟文件系统

```json
{
  "enabled": false
}
```

**适用场景：** 仅使用真实文件系统，不需要虚拟文件功能

## 8. 使用限制

### 8.1 文件大小限制

**默认限制：**
- 最大文件大小：10 MB
- 最大行数：50,000 行

**超出限制时：** 操作被拒绝，返回错误信息

---

### 8.2 行长度限制

**显示限制：** 单行超过 2000 字符时截断显示

**存储：** 完整内容仍然保留在存储中

---

### 8.3 性能考虑

**内存占用：**
- 文件内容存储在内存中
- 大量大文件可能导致内存压力
- 建议配合大结果驱逐机制使用

**State 大小：**
- LangGraph State 有大小限制
- 过多文件可能影响 checkpoint 性能

## 10. 最佳实践

### 10.1 文件组织建议

**临时文件：**
- 使用 `/workspace/` 或 `/tmp/` 前缀
- 会话结束后自动清理

**长期文件：**
- 使用 `/memories/` 前缀
- 按功能分类组织

**驱逐文件：**
- 系统自动管理，无需手动干预

---

### 10.2 性能优化建议

**减少文件数量：**
- 合并相关内容到同一文件
- 及时删除不需要的临时文件

**控制文件大小：**
- 避免存储超大文件
- 使用外部存储（如数据库）存储大数据

**分页读取：**
- 大文件使用 offset 和 limit 参数分批读取

---

### 10.3 错误处理

**常见错误：**

- 文件不存在：检查路径是否正确
- 文件已存在：使用 edit 而非 write
- 权限错误：检查 Store 配置
- 大小超限：减小文件内容
