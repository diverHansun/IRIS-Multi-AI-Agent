# 迁移指南

## 1. 概述

本文档指导现有项目从单一虚拟文件系统架构迁移到双文件系统架构（虚拟 + 真实）。

**迁移目标：**
- 保持现有虚拟文件系统功能完全兼容
- 新增真实文件系统访问能力
- 最小化代码变更
- 平滑过渡，无破坏性更新

---

**工具列表：**

- `read_file`

## 4. 迁移步骤

### 4.1 阶段一：准备工作

**步骤1：备份现有配置**

```bash
cp config/agents/deep/middleware/filesystem.json \
   config/agents/deep/middleware/filesystem.backup.json
```

**步骤2：检查现有依赖**

查找项目中所有使用文件系统工具的地方：

```bash
grep -r "FilesystemMiddleware" src/
grep -r "read_file\|write_file\|edit_file\|list_files" src/
```

**步骤3：记录自定义配置**

如果对文件系统中间件有自定义配置，记录下来以便迁移。

---

### 4.2 阶段二：代码迁移

**步骤1：更新导入路径**

如果代码中直接导入了文件系统中间件：

```python
# 旧的导入方式（仍然兼容）
from deepagents.middleware.filesystem import FilesystemMiddleware

# 新的导入方式
from deepagents.runtime_middlewares.virtual_filesystem import VirtualFilesystemMiddleware
from deepagents.runtime_middlewares.real_filesystem import RealFilesystemMiddleware
```

**步骤2：更新中间件配置**

```python
# 旧配置
middleware = FilesystemMiddleware(
    long_term_memory=True,
    tool_token_limit_before_evict=20000,
)

# 新配置：分离为两个中间件
virtual_fs = VirtualFilesystemMiddleware(
    long_term_memory=True,
    tool_token_limit_before_evict=20000,
)

real_fs = RealFilesystemMiddleware(
    enabled=True,
    # 配置详见真实文件系统文档
)

# 注册到 Agent
agent = DeepAgent(
    middlewares=[virtual_fs, real_fs],
    # ...
)
```

---

### 4.3 阶段三：配置文件迁移

**步骤1：创建虚拟文件系统配置**

```bash
cp config/agents/deep/middleware/filesystem.json \
   config/agents/deep/middleware/virtual_filesystem.json
```

编辑 `virtual_filesystem.json`，简化配置：

```json
{
  "enabled": true,
  "long_term_memory": true,
  "tool_token_limit_before_evict": 20000
}
```

移除不必要的安全配置（虚拟文件系统不需要）。

**步骤2：创建真实文件系统配置**

创建 `config/agents/deep/middleware/real_filesystem.json`：

```json
{
  "enabled": true,
  "project_root": "${PROJECT_ROOT}",
  "security": {
    "allowed_paths": [
      "${PROJECT_ROOT}/src",
      "${PROJECT_ROOT}/docs"
    ],
    "excluded_paths": [
      "${PROJECT_ROOT}/.git",
      "${PROJECT_ROOT}/.env"
    ],
    "allowed_extensions": [
      ".py", ".js", ".ts", ".md", ".txt", ".json"
    ],
    "max_file_size": 10485760
  }
}
```

根据项目实际情况调整路径配置。

---

### 4.4 阶段四：测试验证

**步骤1：单元测试**

运行文件系统相关的单元测试，确保功能正常：

```bash
pytest tests/unit/deepagents/test_filesystem*.py
```

**步骤2：集成测试**

测试 Agent 使用文件系统工具的场景：

```python
# 测试虚拟文件系统
agent.run("创建一个临时文件记录分析结果")

# 测试真实文件系统
agent.run("读取项目的 README.md")
agent.run("找到所有 Python 文件")
```

**步骤3：端到端测试**

运行完整的 Agent 工作流，确保所有功能正常。

## 5. 向后兼容性

### 5.1 旧工具名称支持

为了向后兼容，虚拟文件系统工具保留旧名称作为别名：

| 新名称 | 旧名称 | 状态 |
|--------|--------|------|
| `list_virtual_files` | `ls`, `list_files` | 两者都可用 |
| `read_virtual_file` | `read_file` | 两者都可用 |
| `write_virtual_file` | `write_file` | 两者都可用 |
| `edit_virtual_file` | `edit_file` | 两者都可用 |

**建议：** 新代码使用新名称，旧代码保持不变。

---

### 5.2 旧配置文件支持

如果保留 `filesystem.json` 而不创建 `virtual_filesystem.json`，系统会自动将其作为虚拟文件系统配置加载。

**兼容逻辑：**

```python
# 优先级：virtual_filesystem.json > filesystem.json
if os.path.exists("virtual_filesystem.json"):
    load_config("virtual_filesystem.json")
elif os.path.exists("filesystem.json"):
    load_config("filesystem.json")  # 向后兼容
```

---

### 5.3 旧导入路径支持

旧的导入路径继续可用：

```python
# 旧路径（继续支持）
from deepagents.middleware.filesystem import FilesystemMiddleware

# 内部重定向到
from deepagents.runtime_middlewares.virtual_filesystem import VirtualFilesystemMiddleware
```

## 6. 常见问题

### 6.1 为什么要拆分成两个中间件？

**回答：**

- 职责分离：虚拟文件系统管理内部数据，真实文件系统访问外部信息
- 安全隔离：真实文件系统需要严格的权限控制，虚拟文件系统不需要
- 灵活配置：可以独立启用或禁用任一文件系统
- 便于维护：代码更清晰，测试更简单

---

### 6.2 现有的虚拟文件会丢失吗？

**回答：**

不会。虚拟文件系统的存储机制没有改变，所有现有数据（包括长期记忆）都会保留。

---

### 6.3 需要修改所有 Agent 的 System Prompt 吗？

**回答：**

不需要手动修改。中间件会自动向 System Prompt 添加工具说明。但建议在 Agent 的自定义 prompt 中明确说明两套文件系统的区别。

---

### 6.4 真实文件系统是否默认启用？

**回答：**

否。真实文件系统需要显式配置和启用。如果不需要访问宿主机文件，可以不启用。

---

### 6.5 如何确认迁移成功？

**回答：**

检查以下几点：

- Agent 能正常使用虚拟文件系统（创建、读取、编辑文件）
- Agent 能正常使用真实文件系统（读取项目文件）
- 长期记忆功能正常
- 大结果驱逐功能正常
- 没有错误日志

## 8. 最佳实践

### 8.1 渐进式迁移

**建议步骤：**

1. 先部署虚拟文件系统（保持现有功能）
2. 测试稳定后，再启用真实文件系统
3. 逐步将需要访问宿主机文件的功能迁移到真实文件系统工具

---

### 8.2 配置管理

**建议：**

- 为不同环境（开发、测试、生产）准备不同的配置文件
- 使用版本控制管理配置文件
- 敏感路径配置使用环境变量

---

### 8.3 监控和日志

**建议：**

- 记录文件系统工具的使用情况
- 监控错误率和性能
- 定期审查真实文件系统的访问日志

## 11. 总结
