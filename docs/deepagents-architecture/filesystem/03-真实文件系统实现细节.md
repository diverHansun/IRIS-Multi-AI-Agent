# 真实文件系统实现细节

## 1. 概述

真实文件系统中间件提供对宿主机文件系统的只读访问能力，使 Agent 能够读取项目代码、配置文件和文档。通过严格的权限控制确保系统安全。

**核心原则：只读、受限、可控**

---

## 2. 安全模型

### 2.1 多层安全防护

真实文件系统采用多层安全防护机制：

**第一层：路径白名单**
- 只能访问配置中明确允许的目录
- 路径必须匹配白名单中的某个前缀

**第二层：路径黑名单**
- 明确禁止访问的敏感目录
- 黑名单优先级高于白名单

**第三层：文件类型限制**
- 只能访问特定扩展名的文件
- 拒绝可执行文件、系统文件等

**第四层：文件大小限制**
- 拒绝读取超大文件
- 防止内存溢出和性能问题

**第五层：只读限制**
- 不提供任何写入、编辑、删除工具
- 从架构层面确保只读

---

### 2.2 路径白名单机制

白名单定义允许访问的目录前缀：

```json
"allowed_paths": [
  "${PROJECT_ROOT}",
  "${HOME}/documents"
]
```

**匹配规则：**

- 请求路径必须以白名单中某个路径开头
- 支持环境变量和相对路径
- 路径规范化后再进行匹配

**路径解析顺序：**

1. 环境变量替换（如 `${PROJECT_ROOT}`）
2. 相对路径解析（基于项目根目录）
3. 路径规范化（统一斜杠、移除 `.` 等）
4. 白名单匹配检查

---

### 2.3 路径黑名单机制

黑名单定义明确禁止访问的目录：

```json
"excluded_paths": [
  "/etc",
  "/sys",
  "${HOME}/.ssh",
  "${HOME}/.env"
]
```

**匹配规则：**

- 请求路径与黑名单任一路径匹配则拒绝
- 黑名单检查在白名单之后进行
- 黑名单优先级最高

---

### 2.4 文件类型白名单

只允许读取特定扩展名的文件：

```json
"allowed_extensions": [
  ".py", ".js", ".ts", ".java", ".go",
  ".md", ".txt", ".json", ".yaml", ".yml",
  ".html", ".css", ".sql", ".sh"
]
```

**特殊处理：**

- 无扩展名的文件需要特别配置
- 可以使用通配符 `*` 表示允许所有类型

---

### 2.5 文件大小限制

防止读取超大文件：

**默认限制：** 10 MB

**超限处理：**
- 读取前检查文件大小
- 超限则拒绝读取并返回错误
- 错误信息包含文件大小和限制值

---

## 3. 路径解析

### 3.1 跨平台路径支持

真实文件系统需要处理不同操作系统的路径格式：

**Windows：**
- 支持反斜杠：`C:\Users\user\project`
- 支持驱动器号：`C:`, `D:` 等
- 统一转换为正斜杠用于内部处理

**Linux/Mac：**
- 标准 POSIX 路径：`/home/user/project`
- 支持符号链接（需谨慎处理）

---

### 3.2 相对路径解析

支持相对于项目根目录的路径：

**项目根目录识别：**
- 通过环境变量：`PROJECT_ROOT`
- 通过配置文件：`project_root`
- 自动检测：向上查找 `.git` 或特定标记文件

**相对路径转换：**

```
输入：./src/main.py
基础：/home/user/project
输出：/home/user/project/src/main.py
```

---

### 3.3 环境变量替换

配置中的路径支持环境变量：

**支持的变量：**
- `${PROJECT_ROOT}`：项目根目录
- `${HOME}`：用户主目录
- `${CWD}`：当前工作目录
- 其他自定义环境变量

**替换时机：** 配置加载时一次性替换

---

### 3.4 路径规范化

所有路径经过规范化处理：

**规范化步骤：**

1. 环境变量替换
2. 相对路径解析
3. 反斜杠转换为正斜杠
4. 移除多余的斜杠和 `.` 组件
5. 解析符号链接（可选）
6. 转换为绝对路径

**安全检查：**

- 拒绝包含 `..` 的路径（防止目录遍历）
- 拒绝符号链接指向白名单外的路径

---

## 4. 工具实现

### 4.1 list_real_files

**功能：** 列出指定目录下的文件

**参数：**
- `directory_path`：目录路径（默认为配置的第一个白名单路径）
- `recursive`：是否递归列出子目录（默认 False）
- `include_hidden`：是否包含隐藏文件（默认 False）

**返回：** 文件路径列表

**实现细节：**

- 路径安全检查
- 使用 `os.listdir` 或 `os.walk` 遍历目录
- 过滤不符合扩展名要求的文件
- 过滤隐藏文件（可选）
- 返回相对路径或绝对路径

**错误处理：**

- 目录不存在
- 权限不足
- 不在白名单内

---

### 4.2 read_real_file

**功能：** 读取真实文件内容

**参数：**
- `file_path`：文件路径（必须）
- `offset`：起始行号（默认 0）
- `limit`：读取行数（默认 2000）
- `encoding`：文件编码（默认 utf-8）

**返回：** 带行号的文件内容

**实现细节：**

- 路径安全检查（白名单、黑名单、扩展名）
- 文件大小检查
- 使用适当的编码读取文件
- 按行分割内容
- 支持分页读取（offset + limit）
- 添加行号格式化

**输出格式：**

```
     1  line content 1
     2  line content 2
     3  line content 3
```

**错误处理：**

- 文件不存在
- 权限不足
- 文件过大
- 编码错误
- 不在白名单内

**编码处理：**

- 优先使用指定编码
- 编码错误时尝试自动检测
- 无法解码时返回错误

---

### 4.3 glob_real_files

**功能：** 按通配符模式搜索文件

**参数：**
- `pattern`：Glob 模式（如 `*.py`, `**/*.js`）
- `base_path`：搜索基础路径（默认为白名单路径）
- `recursive`：是否递归搜索（默认 True）

**返回：** 匹配的文件路径列表

**实现细节：**

- 使用 Python 的 `glob` 模块或 `pathlib`
- 支持标准 Glob 语法：
  - `*`：匹配任意字符（不包括路径分隔符）
  - `**`：递归匹配目录
  - `?`：匹配单个字符
  - `[abc]`：匹配字符集
- 结果过滤：只返回白名单内的文件
- 按路径排序返回

**Glob 模式示例：**

- `*.py`：当前目录的所有 Python 文件
- `**/*.py`：递归搜索所有 Python 文件
- `src/**/*.test.js`：src 目录下所有测试文件
- `config/*.{json,yaml}`：config 目录下的 JSON 和 YAML 文件

**错误处理：**

- 模式语法错误
- 基础路径不在白名单内
- 权限不足

**性能考虑：**

- 大型项目可能返回数千个文件
- 支持结果数量限制
- 建议使用更具体的模式

---

### 4.4 grep_real_files

**功能：** 在文件内容中搜索文本模式

**参数：**
- `pattern`：正则表达式模式
- `file_pattern`：文件过滤模式（可选，如 `*.py`）
- `base_path`：搜索基础路径（可选）
- `case_sensitive`：是否区分大小写（默认 True）
- `context_lines`：显示匹配行前后的上下文行数（默认 0）
- `max_results`：最大结果数（默认 100）

**返回：** 格式化的搜索结果

**实现细节：**

- 使用 glob 筛选要搜索的文件
- 使用 `re` 模块进行正则匹配
- 支持大小写敏感/不敏感
- 支持上下文行显示
- 限制结果数量防止输出过大

**输出格式：**

```
文件: /path/to/file1.py
  12: matched line content
  25: another matched line

文件: /path/to/file2.py
  5: matched line here
```

**上下文显示：**

```
文件: /path/to/file.py
  10  context before
  11  context before
  12: MATCHED LINE
  13  context after
  14  context after
```

**性能优化：**

- 跳过二进制文件
- 超过 max_results 后停止搜索
- 跳过白名单外的文件
- 大文件按块读取

**错误处理：**

- 正则表达式语法错误
- 文件编码错误（跳过该文件）
- 权限不足（跳过该文件）

## 5. 配置选项

### 5.1 配置文件位置

```
config/agents/deep/middleware/filesystem/real_filesystem.json
```

---

### 5.2 配置文件结构

```json
{
  "enabled": true,
  "project_root": "${AUTO_DETECT}",
  "security": {
    "allowed_paths": [
      "${PROJECT_ROOT}/src",
      "${PROJECT_ROOT}/docs",
      "${PROJECT_ROOT}/tests"
    ],
    "excluded_paths": [
      "${PROJECT_ROOT}/.git",
      "${PROJECT_ROOT}/.env",
      "${PROJECT_ROOT}/node_modules"
    ],
    "allowed_extensions": [
      ".py", ".js", ".ts", ".java", ".go",
      ".md", ".txt", ".json", ".yaml"
    ],
    "max_file_size": 10485760
  },
  "performance": {
    "glob_max_results": 1000,
    "grep_max_results": 100,
    "grep_max_file_size": 1048576
  },
  "advanced": {
    "follow_symlinks": false,
    "case_sensitive": true,
    "ignore_hidden_files": true
  }
}
```

---

### 5.3 配置参数详解

#### 5.3.1 enabled

**类型：** 布尔值

**默认值：** `true`

**说明：** 控制是否启用真实文件系统中间件

**作用：**
- `true`：加载真实文件系统，Agent 可以读取宿主机文件
- `false`：禁用真实文件系统，Agent 无法访问宿主机文件

**使用建议：**
- 需要 Agent 读取项目代码、文档时启用
- 纯计算任务或安全敏感环境可禁用

---

#### 5.3.2 project_root

**类型：** 字符串

**默认值：** `"${AUTO_DETECT}"`

**说明：** 项目根目录路径，用于相对路径解析和默认白名单

**支持的值类型：**

1. **自动检测**：`"${AUTO_DETECT}"` 或 `null`
   - 向上查找 `.git` 目录
   - 查找 `pyproject.toml`、`package.json` 等标记文件
   - 失败则使用当前工作目录（CWD）

2. **绝对路径**：`"/home/user/my-project"`
   - 直接使用指定的绝对路径

3. **相对路径**：`"./my-project"` 或 `"../another-project"`
   - 相对于当前工作目录解析

4. **环境变量**：`"${HOME}/projects/my-app"`
   - 支持 `${HOME}`、`${CWD}` 等环境变量
   - 启动时自动替换

**解析优先级：**
1. 检查是否为 `${AUTO_DETECT}` 或 `null` → 执行自动检测
2. 环境变量替换
3. 判断绝对路径 vs 相对路径
4. 路径规范化和验证

**使用建议：**
- 推荐使用 `${AUTO_DETECT}`，适应不同部署环境
- 多项目场景可使用环境变量配置
- 避免硬编码绝对路径

---

#### 5.3.3 security.allowed_paths

**类型：** 字符串数组

**默认值：** `["${PROJECT_ROOT}"]`（如果未配置）

**说明：** 白名单路径列表，Agent 只能访问这些路径下的文件

**路径匹配规则：**
- 请求路径必须以白名单中某个路径开头
- 支持环境变量（如 `${PROJECT_ROOT}`、`${HOME}`）
- 支持绝对路径和相对路径
- 路径规范化后进行匹配

**配置策略：**

| 策略 | 配置示例 | 说明 |
|------|----------|------|
| 全项目访问 | `["${PROJECT_ROOT}"]` | 允许访问整个项目 |
| 分目录限制 | `["${PROJECT_ROOT}/src", "${PROJECT_ROOT}/docs"]` | 只允许特定目录 |
| 多项目访问 | `["/project1", "/project2"]` | 跨项目访问 |
| 用户目录 | `["${HOME}/documents"]` | 访问用户文档 |

**安全注意事项：**
- 必须至少配置一个路径，否则无法访问任何文件
- 避免配置系统敏感目录（如 `/etc`、`/sys`）
- 使用最小权限原则，只开放必要目录

---

#### 5.3.4 security.excluded_paths

**类型：** 字符串数组

**默认值：** `[]`

**说明：** 黑名单路径列表，明确禁止访问的目录

**优先级：** 黑名单优先级高于白名单

**常见排除目录：**

```json
[
  "${PROJECT_ROOT}/.git",           // Git 仓库数据
  "${PROJECT_ROOT}/.env",           // 环境变量文件
  "${PROJECT_ROOT}/.env.local",     // 本地环境变量
  "${PROJECT_ROOT}/.venv",          // Python 虚拟环境
  "${PROJECT_ROOT}/venv",
  "${PROJECT_ROOT}/node_modules",   // Node.js 依赖
  "${PROJECT_ROOT}/__pycache__",    // Python 缓存
  "${PROJECT_ROOT}/.pytest_cache",  // Pytest 缓存
  "${PROJECT_ROOT}/dist",           // 构建产物
  "${PROJECT_ROOT}/build",
  "${HOME}/.ssh",                   // SSH 密钥
  "${HOME}/.aws"                    // AWS 凭证
]
```

**使用建议：**
- 排除包含敏感信息的文件和目录
- 排除大型依赖目录（提升性能）
- 排除缓存和临时文件目录

---

#### 5.3.5 security.allowed_extensions

**类型：** 字符串数组

**默认值：** 常见代码和文档格式

**说明：** 允许读取的文件扩展名白名单

**推荐配置：**

```json
[
  // 编程语言
  ".py", ".js", ".ts", ".jsx", ".tsx",
  ".java", ".go", ".rs", ".cpp", ".c", ".h",
  ".rb", ".php", ".cs", ".swift", ".kt",

  // 配置和数据
  ".json", ".yaml", ".yml", ".toml", ".ini", ".cfg",
  ".xml", ".csv", ".env.example",

  // 文档
  ".md", ".txt", ".rst", ".adoc",

  // Web
  ".html", ".css", ".scss", ".sass", ".less",

  // 脚本
  ".sh", ".bash", ".zsh", ".ps1", ".bat",

  // SQL
  ".sql"
]
```

**特殊值：**
- `["*"]`：允许所有文件类型（不推荐，安全风险）
- `[]`：不允许任何文件（等同于禁用）

**安全建议：**
- 明确指定需要的扩展名
- 避免使用通配符 `*`
- 排除可执行文件（`.exe`、`.dll`、`.so`）
- 排除二进制文件（`.bin`、`.dat`）

---

#### 5.3.6 security.max_file_size

**类型：** 整数（字节）

**默认值：** `10485760`（10 MB）

**说明：** 单个文件的最大读取大小

**常见值：**

| 大小 | 字节数 | 适用场景 |
|------|--------|----------|
| 1 MB | 1048576 | 严格限制，只读小文件 |
| 5 MB | 5242880 | 一般代码文件 |
| 10 MB | 10485760 | 默认推荐值 |
| 50 MB | 52428800 | 大型配置文件或数据 |

**超限处理：**
- 读取前检查文件大小
- 超限则拒绝并返回错误信息
- 不会部分读取

**调优建议：**
- 根据实际文件大小分布调整
- 过小会导致大文件无法读取
- 过大可能导致内存问题

---

#### 5.3.7 performance.glob_max_results

**类型：** 整数

**默认值：** `1000`

**说明：** glob 搜索返回的最大文件数

**作用：**
- 防止大型项目返回数万个文件
- 达到上限后停止搜索
- 保护 Agent context 不被撑爆

**调优建议：**

| 项目规模 | 推荐值 |
|----------|--------|
| 小型（< 100 文件） | 500 |
| 中型（100-1000 文件） | 1000 |
| 大型（> 1000 文件） | 2000 |

**注意事项：**
- 达到上限时会返回警告信息
- 建议 Agent 使用更具体的搜索模式

---

#### 5.3.8 performance.grep_max_results

**类型：** 整数

**默认值：** `100`

**说明：** grep 搜索返回的最大匹配数

**作用：**
- 限制输出结果数量
- 避免大量匹配淹没 Agent
- 提升响应速度

**调优建议：**

| 场景 | 推荐值 |
|------|--------|
| 精确搜索 | 50 |
| 一般搜索 | 100 |
| 宽泛搜索 | 200 |

---

#### 5.3.9 performance.grep_max_file_size

**类型：** 整数（字节）

**默认值：** `1048576`（1 MB）

**说明：** grep 搜索时单个文件的大小限制

**作用：**
- 跳过超大文件，避免性能问题
- 大文件通常是日志或数据，不是搜索目标

**推荐值：** 1 MB - 5 MB

---

#### 5.3.10 advanced.follow_symlinks

**类型：** 布尔值

**默认值：** `false`

**说明：** 是否跟随符号链接

**安全考虑：**
- `false`：不跟随符号链接，更安全
- `true`：跟随符号链接，可能绕过白名单

**使用建议：**
- 默认禁用，防止链接攻击
- 确有需要时启用，并配合严格的白名单

---

#### 5.3.11 advanced.case_sensitive

**类型：** 布尔值

**默认值：** `true`

**说明：** 路径匹配是否区分大小写

**平台差异：**
- Linux/Mac：文件系统区分大小写，建议 `true`
- Windows：文件系统不区分大小写，可设为 `false`

---

#### 5.3.12 advanced.ignore_hidden_files

**类型：** 布尔值

**默认值：** `true`

**说明：** 是否忽略隐藏文件（以 `.` 开头）

**作用：**
- `true`：跳过 `.gitignore`、`.DS_Store` 等隐藏文件
- `false`：包含所有文件

**使用建议：**
- 一般场景启用，减少干扰
- 需要分析配置文件时禁用

---

### 5.4 project_root 解析规则详解

#### 自动检测流程

当 `project_root` 设置为 `${AUTO_DETECT}` 或 `null` 时：

**步骤 1：** 从当前工作目录开始向上查找

**步骤 2：** 按顺序检测标记文件：
1. `.git` 目录（Git 仓库）
2. `pyproject.toml`（Python 项目）
3. `package.json`（Node.js 项目）
4. `Cargo.toml`（Rust 项目）
5. `go.mod`（Go 项目）
6. `pom.xml`（Java Maven 项目）
7. `build.gradle`（Java Gradle 项目）

**步骤 3：** 找到第一个标记文件后，返回其所在目录

**步骤 4：** 如果未找到，使用当前工作目录（CWD）

---

#### 环境变量支持

**预定义变量：**
- `${PROJECT_ROOT}`：项目根目录（解析后的值）
- `${HOME}`：用户主目录
- `${CWD}`：当前工作目录
- `${USER}`：当前用户名

**自定义变量：**
- 支持任意系统环境变量
- 格式：`${VARIABLE_NAME}`

**示例：**
```json
{
  "project_root": "${MY_PROJECT_PATH}",
  "security": {
    "allowed_paths": [
      "${PROJECT_ROOT}/src",
      "${HOME}/shared-docs"
    ]
  }
}
```

### 5.5 配置示例

#### 最小配置（推荐）


## 7. 错误处理

### 7.1 安全相关错误

**路径不在白名单：**

```
错误: 路径 '/etc/passwd' 不在允许访问的目录中
允许的路径: ['/home/user/project']
```

**路径在黑名单：**

```
错误: 路径 '/home/user/.ssh/id_rsa' 明确被禁止访问
```

**文件类型不允许：**

```
错误: 不允许访问扩展名为 '.exe' 的文件
允许的扩展名: ['.py', '.js', '.md', ...]
```

---

### 7.2 文件系统错误

**文件不存在：**

```
错误: 文件 '/path/to/file.py' 不存在
```

**权限不足：**

```
错误: 无权限读取文件 '/path/to/file.py'
```

**文件过大：**

```
错误: 文件大小 15MB 超过限制 10MB
```

---

### 7.3 编码相关错误

**编码错误：**

```
错误: 无法使用 UTF-8 解码文件
建议: 尝试指定其他编码或跳过此文件
```

**二进制文件：**

```
警告: 文件 'image.png' 是二进制文件，跳过
```
